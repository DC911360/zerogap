# ZeroGap｜脑机接口技术验证方案

### BCI Technical Validation Plan

> **文档状态：** 计划中。本文档提出研究框架与验证路径，尚未开展实验。文中涉及的能力均为待验证假设，不代表已经实现的技术水平。

## 1. 文档目的

本文档定义 ZeroGap 在脑机接口（BCI）方向的验证目标、技术路线、实验设计、评估指标与安全边界。

它不是产品规格说明书，也不是对 BCI 能力的承诺。它的作用是：

- 明确我们希望验证什么问题。
- 说明在什么条件下，一个结果可以被认为具有参考价值。
- 划定现阶段不应跨越的技术与伦理边界。

## 2. 为什么关注脑机接口

ZeroGap 关注从人的意图到真实行动之间的链路。现有输入方式——键盘、鼠标、触摸屏、语音——已经覆盖了大量场景，但并不适合所有人。

对于部分因疾病、损伤或身体功能受限而难以使用传统设备的人，表达意图本身就可能构成障碍。脑机接口提供了一种值得研究的方向：能否通过神经信号，为特定任务提供一种新的、有限的意图输入通道。

同时需要明确：BCI 解决的是“如何表达”，而不是“如何完成”。即使意图能够被识别，系统仍然需要理解目标、规划步骤、执行操作并验证结果。这也是 BCI 需要与 Agent 能力分开验证、再讨论结合的原因。

## 3. 范围与非目标

### 3.1 研究范围

- 优先采用非侵入式脑电（EEG）方案。
- 聚焦有限、离散的控制意图，而不是开放式自然语言意图。
- 先在受控环境中完成离线分析与实时闭环验证。
- 探索将稳定的输入事件接入 Agent 的可行性。
- 评估与传统输入方式相比的实际净收益。

### 3.2 非目标

现阶段不承诺、也不将以下内容作为研究目标：

- 读取任意思想、情绪或复杂心理状态。
- 侵入式植入或神经刺激类产品能力。
- 医疗诊断、治疗或康复效果。
- 跨用户、跨设备、跨场景的通用稳定解码。
- 将实验原型直接作为产品能力对外宣传。

## 4. 技术路线

### 4.1 信号采集

设备选型需要评估：

- 采样率、通道数量与电极类型。
- 信号质量、阻抗稳定性与抗干扰能力。
- 是否提供可用的数据接口与开发文档。
- 佩戴时间、舒适度与校准复杂度。
- 在目标使用环境中的可行性。

研究早期优先使用成熟的商用或科研设备，不自行设计硬件。

### 4.2 预处理

典型处理包括滤波、伪迹识别与去除、分段、基线校正与坏段剔除。

需要特别区分脑电活动与眼电、肌电、设备接触不良等非脑源信号。例如，眨眼可以产生明显信号，但不能被直接当作“识别出脑电意图”的证据。

### 4.3 特征与解码

可从时域、频域或空域提取特征，并比较不同分类方法。

研究重点不是追求某一次实验的最高准确率，而是判断：

- 特征与目标任务之间是否存在可重复的关系。
- 解码结果在不同会话、不同条件下是否稳定。
- 个体差异对结果的影响有多大。

### 4.4 控制映射

解码结果不应直接等同于操作指令。

系统需要定义：

- 哪些离散事件可以触发操作。
- 每个事件的置信度与数据质量标记。
- 低置信度时的处理方式（重新确认、忽略或停止）。
- 用户如何取消、纠正或撤回操作。

### 4.5 与 Agent 的接口

BCI 模块向 Agent 提供的是“输入事件”，而不是“任务结论”。

一个事件至少应包含：事件类别、置信度、时间戳、数据质量状态与设备标识。具体字段根据设备与研究方案确定。

系统必须允许识别结果为“不确定”，而不是强迫算法对每一次输入都给出动作。

## 5. 关键研究问题

| 编号 | 研究问题 |
|---|---|
| RQ1 | 在受控任务中，特定信号模式能否被可重复地识别？ |
| RQ2 | 识别结果在不同时间与会话之间是否稳定？ |
| RQ3 | 不同被试之间的差异有多大，是否需要个体校准？ |
| RQ4 | 误触发率是否低到足以支持实际交互？ |
| RQ5 | 与现有输入方式相比，是否带来真实的净收益？ |
| RQ6 | 设备佩戴、训练与日常使用负担是否可接受？ |

这些问题需要分别设计实验回答，不能用单一准确率概括。

## 6. 实验设计框架

### 6.1 任务选择

优先选择离散、明确、可重复的任务，例如少量类别的选择或状态切换。

任务设计应避免把非脑源信号（眨眼、咬牙、头部运动）误认为意图识别。

### 6.2 被试与训练

记录被试的基本信息、训练时长、既往设备使用经验与排除标准。

如果涉及人体参与者，应根据研究性质评估是否需要伦理审查与知情同意。

### 6.3 数据采集

固定并记录设备参数、电极位置、环境条件、实验流程与操作人员。

保留原始数据与处理脚本版本，确保结果可追溯。

### 6.4 对照与防偏差

设置合理的对照条件，避免仅凭单次成功判断能力成立。

训练集、验证集与测试集应明确分离，防止数据泄漏导致结果虚高。

### 6.5 记录规范

记录失败案例、异常数据与被试反馈，而不仅是成功样本。

失败数据对于判断系统边界同样重要。

## 7. 评估指标

| 维度 | 指标 |
|---|---|
| 识别效果 | 准确率、召回率、混淆矩阵 |
| 误触发 | 单位时间误触发次数、误触发后果 |
| 实时性 | 从信号采集到事件输出的延迟 |
| 稳定性 | 跨会话、跨时间段的性能变化 |
| 可用性 | 训练时间、校准时间、佩戴负担 |
| 交互效率 | 完成目标任务所需时间与步骤 |
| 净收益 | 与传统输入方式相比的实际改善 |
| 用户感受 | 可控性、理解成本、接受度 |

指标应在实验开始前定义，并在报告中同时给出样本量、实验条件与局限性。

## 8. 安全、伦理与数据治理

- 涉及人体参与者时，根据适用要求落实知情同意、风险说明与退出机制。
- 神经信号属于敏感数据，应遵循最小化采集、目的限制、访问控制与保存期限管理。
- 不将实验数据用于未告知参与者的用途。
- 对高风险操作设置额外确认；识别不确定时优先停止，而不是猜测。
- 不把研究原型用于诊断、治疗或其他超出验证范围的用途。
- 对弱势群体参与研究设置额外保护措施。

## 9. 分阶段计划

| 阶段 | 目标 | 退出条件 |
|---|---|---|
| 阶段 0：调研与设备评估 | 完成文献梳理、设备选型与合作方评估 | 形成明确的实验任务与设备方案 |
| 阶段 1：离线验证 | 验证特定任务下信号与标签的关系 | 结果可重复，且明确适用条件 |
| 阶段 2：受控实时闭环 | 将解码结果映射为低风险 UI 事件 | 延迟、误触发与稳定性达到预设标准 |
| 阶段 3：接入 Agent | 将稳定的输入事件接入 Agent 任务流程 | 端到端任务可完成，异常可处理 |
| 阶段 4：场景评估 | 在明确场景中评估真实价值与风险 | 有证据支持继续投入或停止 |

每个阶段都应允许得出“当前条件不支持继续”的结论。

## 10. 与跨平台 Agent 的集成边界

BCI 是输入层的一种潜在方式，不是 Agent 的前置条件。

集成时应遵循：

- BCI 只提供有限的输入事件，不替代目标理解、任务规划、执行与验证。
- 输入事件必须携带置信度与质量信息。
- 低置信度事件应触发确认或忽略，而不是自动执行。
- 高风险任务不应仅凭单次识别结果执行。
- BCI 能力的验证与 Agent 能力的验证应分别进行，再评估结合价值。
