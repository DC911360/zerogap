# ZeroGap

### From Intent to Action, Without Steps.

> [中文版 README](README.md) · English summary for international readers. The full project documents are currently written in Chinese.

## The Problem

People usually know what they want to accomplish. Yet turning that intent into real action still requires a long chain of manual work: finding the right app, learning its interface, switching between systems, passing information along, and checking whether anything actually happened.

We call the unnecessary part of that chain the **Gap** — the distance between human intent and real action. It is not only about the number of clicks. It includes understanding, expression, execution, coordination, verification, and accessibility.

## What We're Building

ZeroGap explores two complementary paths:

- **A cross-platform AI agent (near term).** A system that understands a goal, plans the steps, coordinates tools across applications, executes within explicit permissions, and verifies the result — rather than only generating an answer.
- **Brain-computer interfaces (long term).** An exploration of new intent-input channels, especially for people with limited mobility. BCI is treated as a research direction, not a mature product capability.

The two paths address different parts of the same chain: BCI asks how intent can be expressed more naturally; the agent asks how intent can be turned into reliable, verifiable action.

## Why Now

Large language models make natural-language goal understanding practical. Agent tooling, cross-platform automation, and model context management are maturing. BCI research is advancing, but remains experimental and requires rigorous validation.

This does not mean the problem is solved. It means there is a reasonable window to build prototypes, test assumptions, and learn from real tasks.

- **Next milestone:** validate one low-risk, end-to-end task — from goal understanding and tool execution to result verification and clear feedback.

## How We Think About the Problem

We organize the Gap into six areas: understanding, expression, execution, coordination, verification, and accessibility. A useful system must address the whole chain, not a single step.

Our design principles follow from that view:

- Reduce unnecessary steps, but preserve necessary control.
- Give the system the minimum permissions required for the task.
- Judge completion by real results, not by the model's own claim.
- Be honest about uncertainty and technical limits.
- Keep humans informed, able to intervene, and able to stop.
