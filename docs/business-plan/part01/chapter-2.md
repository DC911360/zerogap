## 第二章 时代背景：人机交互正在发生什么变化

### 2.1 每一次技术革命，都在重新定义人与机器的关系

回顾计算技术的发展，人类与机器的关系一直在变化。

早期的计算机属于少数专业人员。使用计算机意味着学习命令、理解操作规则，并通过严格的指令告诉机器应该做什么。

随后，图形用户界面改变了这一切。

窗口、图标、菜单与鼠标，让人们不再需要记住大量命令，而是可以通过视觉和操作与计算机交流。个人电脑因此逐渐走进办公室与家庭。

智能手机进一步改变了交互方式。触摸屏、移动网络、传感器与应用生态，让计算能力进入日常生活。人们可以随时随地获取信息、沟通协作、处理事务，也可以通过位置、动作与环境信息和设备进行交互。

此后，语音助手与自然语言交互开始尝试让人们摆脱部分传统操作流程。人们可以直接说出需求，而不必总是寻找按钮和菜单。

今天，大语言模型与 AI Agent 的发展，又带来了新的可能性。

如果说传统软件主要让人通过界面操作功能，那么新一代智能系统正在尝试理解人的目标，并在一定范围内承担完成目标所需的工作。

这不只是交互界面的变化，更可能是人与软件之间分工方式的变化。

过去，人负责理解任务、寻找工具、组织步骤并执行操作，软件提供相应的功能。

未来，人可以更多地负责提出目标、表达约束、做出关键决策，而智能系统承担一部分信息处理、任务协调与具体执行工作。

这并不意味着机器将全面替代人的判断，而是意味着人和机器之间可能形成新的协作关系。

**人机交互的下一阶段，值得探索的方向，是从让人更方便地操作软件，走向让软件更好地理解并协助实现人的目标。**

这正是 ZeroGap 关注的时代变化。

### 2.2 大语言模型：机器开始理解更接近人类的表达

过去，人和计算机交流，通常需要遵循软件预先设计好的交互规则。

表单要求填写指定字段，搜索框等待关键词，业务系统要求按照固定流程完成操作。人必须将自己的真实需求转换成系统能够接受的形式。

大语言模型改变了部分交互条件。

通过对自然语言的理解与生成，模型能够处理更丰富的表达方式，识别上下文中的关联，并协助完成总结、推理、信息提取、内容生成与代码编写等任务。

这使人与机器之间的沟通开始变得更加灵活。

例如，用户不再只需要输入一个关键词，也可以表达一个相对完整的目标：

「帮我整理最近一周的项目进展，找出尚未解决的问题，并生成一份适合周会讨论的摘要。」

模型可以协助理解这项需求，确定需要的信息，并组织出符合目标的内容。

但大语言模型的意义不只是让机器更会聊天。

当模型能够参与需求理解、任务分解与决策辅助时，它便有机会成为连接人类目标与数字工具的中间层。

当然，自然语言理解并不等于始终正确地理解意图。模型仍然可能误解需求、遗漏约束或生成不准确的信息。因此，系统需要结合上下文、明确的任务规则、外部数据和验证机制，才能提高实际使用中的可靠性。

对于 ZeroGap 而言，大语言模型提供了一项重要的基础能力：

**人可以用更接近自己思考方式的语言表达目标，系统则可以尝试把这些表达转化为可执行的任务。**

### 2.3 从 AI 助手到 AI Agent：从提供答案走向执行任务

能够理解需求，并不代表能够完成任务。

一个 AI 助手可以告诉用户如何安排会议，却未必能够直接创建日程、邀请参与者并确认通知是否发送成功。

一个模型可以生成代码，却未必能够独立完成项目修改、运行测试、处理报错并验证最终结果。

这暴露出一个重要区别：提供建议与完成任务，是两种不同的能力。

AI Agent 的发展，正在探索如何把模型的理解能力与外部工具、执行环境及反馈机制连接起来。

一个具备任务执行能力的 Agent，通常需要完成以下工作：

1. 理解用户的目标与限制条件。
2. 将目标拆解成可执行的任务步骤。
3. 根据任务需要选择合适的工具或外部服务。
4. 执行操作，并读取实际返回结果。
5. 根据结果继续执行、调整计划或处理异常。
6. 检查任务是否达到预期，并向用户报告结果。

这是一种从目标出发、通过执行过程逐步接近目标状态的工作方式。

它也带来了新的挑战。

不同应用有不同的接口与权限体系；执行过程中可能出现网络错误、数据缺失或页面变化；某个步骤成功，并不意味着整个任务成功；涉及重要操作时，系统还必须具备适当的授权与确认机制。

因此，真正有价值的 Agent 不应仅仅是一个能够调用工具的模型，而应该是一个能够在明确边界内组织任务、执行操作、处理反馈并验证结果的系统。

这也是为什么 ZeroGap 将跨平台 Agent 作为优先探索方向。

它不仅与长期愿景直接相关，也可以通过具体的软件原型逐步验证。

我们可以先从有限的任务、有限的工具和明确的权限开始，逐步研究如何让系统承担更多实际工作，而不是一开始就追求无所不能的智能体。

### 2.4 软件生态越丰富，跨平台协作的需求就越明显

现代人的工作和生活，往往分散在多个应用与服务中。

日历管理时间，文档保存信息，即时通信工具负责协作，项目管理软件跟踪任务，浏览器连接各种在线服务，业务系统则处理具体的工作流程。

每一个应用都可能很好地解决某一类问题。

但当一项任务需要跨越多个应用时，复杂性就会重新出现。

例如，完成一次项目周报，可能需要从项目管理系统获取进度，从文档中查找背景信息，从沟通记录中整理决策，再将结果汇总到指定的文档中，并通知相关人员。

对于人来说，这是一项完整的任务。

对于彼此独立的软件来说，它却可能是一系列没有直接关联的操作。

用户不得不在不同应用之间切换，复制数据，确认格式，处理重复信息，并承担各个步骤之间的协调成本。

这些工作未必困难，却会持续占用人的时间和注意力。

当 AI Agent 开始具备理解目标和执行操作的能力后，一个新的问题便出现了：

**能否让智能系统围绕用户的目标组织不同的软件能力，而不再要求用户亲自协调每一个应用？**

这正是跨平台 Agent 值得探索的原因。

在 ZeroGap 的设想中，应用仍然可以保持各自的功能边界，但智能执行系统可以在获得授权的情况下，协调不同工具完成一项完整任务。

实现这一点，既可以依赖正式 API，也可能涉及浏览器自动化、桌面操作或其他经过授权的集成方式。不同方式在稳定性、权限、安全性和维护成本上存在差异，需要根据具体场景选择。

因此，跨平台执行不是简单地把多个工具接到一个模型上，而是需要一套能够管理任务、协调工具、控制权限并验证结果的系统能力。

它是 ZeroGap 从理念走向实际产品的重要切入点。

### 2.5 从固定输入到多模态交互：人表达意图的方式正在扩展

虽然软件的智能程度正在提高，但人和设备之间仍然存在大量交互成本。

键盘适合精确输入，鼠标适合指向与选择，触摸屏适合直接操作界面，语音适合部分自然语言交流，摄像头与各类传感器则可以提供视觉和环境信息。

这些输入方式各有优势，也各有边界。

在不同环境下，人可能不方便打字、不适合语音输入，或者希望通过更加自然的动作完成某些操作。

因此，人机交互并不会因为大语言模型的出现，就只剩下一种输入方式。

更合理的趋势，是根据具体任务、使用环境和用户需求，组合不同的交互通道。

多模态模型的发展，让系统有机会同时处理文本、图像、音频及其他形式的信息。可穿戴设备、环境传感器与新型交互硬件，也在不断拓展人向机器传递信息的方式。

但输入方式的增加，不一定自动带来更好的体验。

如果系统无法理解输入的含义，或者不能将输入转化为有效行动，那么即使交互形式更加丰富，用户仍然需要承担大量后续操作。

ZeroGap 因此更关注交互链路的整体效果，而不是单纯追求输入方式的数量。

无论输入来自键盘、语音、视觉还是未来可能成熟的新型接口，关键问题始终是：

系统能否在合适的上下文中理解用户的意图，并以可靠、可控的方式协助实现目标？

这为 ZeroGap 的产品设计提供了一个重要原则：输入方式可以不断演进，但系统最终需要围绕人的目标组织能力。

### 2.6 脑机接口：探索更接近神经活动的新型输入通道

在各种人机交互方式中，脑机接口提供了一个更加长期、也更具挑战性的研究方向。

脑机接口（Brain-Computer Interface，BCI）旨在建立大脑与外部设备之间的信息通道。不同技术路线可能采用头皮脑电、植入式电极或其他信号采集方式，并通过信号处理与算法解码，将特定神经活动转化为可识别的控制信号。

对于非侵入式脑电方案而言，EEG（Electroencephalography，脑电图）可以用于记录头皮上的电位变化，并研究特定实验条件下的神经活动特征。

例如，在受控实验中，可以研究某些特定状态的分类，或将经过训练和验证的信号映射到简单的设备控制指令。

不过，这并不意味着 EEG 能够直接、准确地读取任意想法。

脑电信号容易受到噪声、肌肉活动、环境条件与个体差异的影响。不同任务的识别难度也可能有很大差异。实际系统还需要面对训练成本、使用者适应性、实时性、误触发和长期稳定性等问题。

因此，脑机接口距离普遍、可靠的日常通用交互，仍然存在需要持续研究和验证的技术障碍。

那么，为什么 ZeroGap 仍然关注这一方向？

因为如果未来某些神经信号能够被稳定地识别，并在合适的场景中转化为控制指令，人和数字系统之间的输入方式就可能出现新的选择。

对于行动受限的人群，某些经过验证的脑机接口应用可能带来具有实际价值的辅助交互能力。对于其他应用场景，它也可能提供不同于传统输入设备的控制方式。

ZeroGap 不会将这种可能性当作已经实现的产品能力，而是希望从小规模、可重复的实验开始，研究信号采集、特征处理、意图分类与设备控制之间的关系。

在这条路线中，我们需要明确区分三个阶段：

- **技术研究：** 确认特定信号和实验任务之间是否存在可重复识别的关系。
- **原型验证：** 检验分类结果能否在受控条件下稳定地映射到简单操作。
- **产品探索：** 在可靠性、可用性、安全性和实际需求得到进一步验证后，再评估具体应用场景。

脑机接口是 ZeroGap 长期愿景中的一项探索，但不应成为软件产品取得早期进展的前提。

### 2.7 一个重要转变：从操作工具到表达目标

综合这些技术变化，我们可以看到，人机交互可能正在经历一个重要转变。

传统的软件使用方式通常围绕功能展开。

用户需要知道某个功能在哪里，应该点击什么，按照什么顺序操作，以及如何判断操作是否成功。

这种方式在许多场景下仍然有效，而且具有明确、可预测的优势。

但对于跨应用、跨步骤的复杂任务，仅仅提供功能可能还不够。

用户真正需要的，往往不是某个按钮，而是一个完成后的状态。

例如，用户希望的不只是创建一个文档，而是整理出一份准确、完整、适合特定受众阅读的报告；不只是打开日历，而是合理安排时间并协调参与者；不只是获得一段代码，而是解决实际问题并确认修改有效。

这意味着，未来的交互系统可能需要同时具备三种能力：

**第一，理解目标。**

系统需要识别用户希望实现的结果，以及完成任务所需的条件、限制与上下文。

**第二，组织行动。**

系统需要根据目标安排步骤，协调工具与外部服务，并在必要时向用户确认。

**第三，验证结果。**

系统需要根据真实的执行反馈判断任务是否完成，而不能只凭生成了一段文本或发出了一条指令，就认定目标已经实现。

这三种能力共同构成了从意图到行动的基本链路。

它也提醒我们：人机交互的改进不能只发生在输入端，还必须延伸到执行与反馈环节。

ZeroGap 的长期探索，正是围绕这条完整链路展开。

### 2.8 ZeroGap 的时代机会：长期愿景与现实起点

当我们把大语言模型、AI Agent、跨平台软件协作和脑机接口放在同一个视角下观察，会发现它们并不是成熟度相同、可以立即组合的技术模块。

它们分别处于不同的发展阶段，也面临不同的工程与研究问题。

大语言模型已经能够支持大量语言理解与内容生成任务，但在复杂场景中仍可能出现错误。

AI Agent 正在探索从理解目标到执行任务的系统化路径，但可靠性、权限控制、异常恢复与结果验证仍然是重要挑战。

跨平台自动化具有明确的现实需求，但不同软件的接口、数据格式和权限体系增加了集成成本。

脑机接口则需要针对具体信号、任务和设备进行实验验证，距离广泛适用的自然交互仍有较长的探索过程。

因此，ZeroGap 不应该把所有技术一次性整合为一个庞大而难以验证的系统。

更合理的策略，是以统一的愿景为方向，以不同技术路线的成熟度为依据，分阶段推进。

在近期，我们可以从软件领域开始，围绕有限的工具和明确的任务，构建能够理解目标、执行跨平台操作并验证结果的 Agent 原型。

在中期，我们可以根据实际需求，逐步拓展工具生态、上下文管理、任务可靠性和多模态交互能力。

在更长期的探索中，再根据脑机接口研究取得的实际进展，评估新的输入方式是否能够与智能执行系统形成有效结合。

这里的阶段划分是一种初步规划，而不是对技术成熟时间的承诺。具体目标需要结合实验结果、用户需求与资源条件持续调整。

我们希望以这样的方式处理创业愿景与现实之间的关系：

既不因为技术尚未成熟，就放弃探索长期可能性；也不因为长期愿景足够吸引人，就忽略当前必须解决的工程问题。

**ZeroGap 的机会，不在于押注某一项热门技术，而在于围绕人的意图与实际行动之间的距离，持续构建能够被验证、能够演进的系统能力。**

### 2.9 本章小结：为什么是现在

技术的发展正在改变人与数字系统之间的分工方式。

大语言模型降低了部分自然语言交互的门槛；AI Agent 开始探索从目标理解到任务执行的完整过程；跨平台工具与自动化能力，为协调不同软件提供了新的实现路径；脑机接口则为未来可能出现的新型输入方式提供了研究方向。

这些变化并不意味着人与机器之间的距离已经消失。

相反，它们让我们更清楚地看到，真正有价值的交互创新，不仅需要更自然的输入，还需要可靠的任务执行、合理的权限控制和可信的结果反馈。

对 ZeroGap 而言，现在是一个值得开始验证的时间窗口。

我们可以先用现有的软件技术解决真实的问题，在可控的范围内建立产品能力，再以严谨的实验逐步探索更长期的人机交互方向。

从现实出发，向未来推进。

这就是 ZeroGap 对时代背景的判断，也是我们选择在此刻开始的原因。
